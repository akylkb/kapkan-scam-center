
# Экранный реквизит для сериала «Капкан» (фейковый скам-центр)

## О проекте
Интерфейсы подпольного колл-центра для съёмок сериала. Реальный бэкенд, API и
данные не нужны и не предполагаются.

**Цель:** картинка, которая держит крупный план и читается на общем плане как
нелегальная финансовая контора.

**Не цель:** рабочий продукт. Не добавляйте настоящие интеграции, авторизацию,
сетевые запросы или сбор данных.

Съёмочная инструкция — в [README.md](README.md).

---

## Три правила, которые определяют архитектуру

Это не обычный веб-проект. Прежде чем что-то менять, учтите:

### 1. Полный офлайн в рантайме
На площадке может не быть интернета. Никаких CDN, внешних шрифтов по сети,
сторонних API. Шрифты подтягиваются на этапе `build` и раздаются приложением.
Проверка: `npm run build && npm start` при выключенной сети.

Единственное исключение — живой мост `/live` ([lib/live/](lib/live/)), и это
не нарушение: он живёт в том же процессе, что раздаёт страницы, и ходит только
на собственный origin по локалке. Запрет касается зависимости от интернета,
а не от локальной сети площадки.

Сборка статическая (`output: 'export'`): `npm run build` кладёт в `out/`
готовые HTML, `npm start` — свой сервер без зависимостей
([scripts/serve.mjs](scripts/serve.mjs)), который эту папку раздаёт.
Следствие для кода: **никакого серверного рантайма нет**. Ни `searchParams`
в серверных компонентах, ни route handlers, ни `next/image` с оптимизацией,
ни middleware — сборка на таком просто упадёт.

### 2. Никакого `Math.random()` в рендере
Всё содержимое генерируется детерминированно через [lib/prng.ts](lib/prng.ts).
Причины две: дубль 1 и дубль 7 должны выглядеть одинаково, иначе не склеится
монтаж; плюс случайность ломает SSR-гидрацию.

Живое движение чисел делается функцией от тика сцены (сумма синусов), см.
[components/shared/LiveNumber.tsx](components/shared/LiveNumber.tsx).

Живая переписка правило не нарушает: это ввод актёра, а не генерация контента.
Фикстурная база диалога остаётся детерминированной, живые реплики ложатся
поверх неё — тем же приёмом, что и правки режиссёра (`overrides`/`injected`).
`Math.random()` не появляется и там: id живых реплик собираются из роли, места
и счётчика отправителя.

### 3. Десять машин — десять разных экранов
`/crm/N/`, `/drops/N/`, `/chat/N/` и `/victim/N/` — весь контент завязан на
номер места.
Одинаковые экраны в общем плане мгновенно выдают декорацию.

Номер лежит в пути, а не в query, именно из-за статического экспорта: каждое
место — отдельный файл на диске. `generateStaticParams` собирает все 99 мест
([lib/seat.ts](lib/seat.ts)). Страницы `/crm`, `/drops`, `/chat`, `/victim`
оставлены как редирект со старых адресов `?seat=N` — ярлыки на машинах площадки.

Одно исключение из «у каждой машины свой номер»: `/chat/N/` и `/victim/N/` —
две половины одного разговора и обязаны идти под общим номером. Номер места
здесь ещё и адрес комнаты в живой шине.

## Стек
- **Next.js 16 (App Router)** + TypeScript
- **Tailwind CSS v4**, тёмная тема, произвольные значения (`text-[11.5px]`)
  используются намеренно — плотность вёрстки важнее канонических классов
- **lucide-react** — иконки
- **lightweight-charts** — только большой график на экране жертвы;
  мелкие графики рисует [Sparkline](components/shared/Sparkline.tsx)

Библиотеки компонентов сознательно нет: дефолты UI-китов дают «обычный SaaS»,
а нужна нестандартная плотная кинематографичная вёрстка.

## Структура

```
app/{crm,drops,chat,victim}/[seat]/  рабочие места, по HTML на каждое место
app/{wall,client,admin}/       экраны без номера места
app/page.tsx                   служебный лаунчер (в кадр не попадает)
scripts/serve.mjs              съёмочный сервер: раздаёт out/ и держит /live
components/{crm,drops,chat,victim,wall,client,admin,shared}/
lib/
  brand.ts       ВСЕ названия в кадре — менять только здесь
  prng.ts        детерминированный генератор
  format.ts      деньги, время, маскировка телефонов и карт
  seat.ts        номер места из пути + список мест для сборки
  fixtures/      генераторы лидов, операторов, свечей, дропов, заливов,
                 личин (personas), переписки (threads), стола чатера (chatdesk)
  live/          живая связь между экранами
  scene/         часы сцены, шина событий, горячие клавиши режиссёра
```

### Движок сцены
[lib/scene/store.ts](lib/scene/store.ts) — часы (тик 250 мс), лента событий и
реакция на команды режиссёра. Подписка через `useSceneValue(selector)`,
селектор обязан возвращать **примитив**: иначе компонент перерисовывается
четыре раза в секунду, а на площадке десять небыстрых машин.

Раскладка хоткеев — [lib/scene/events.ts](lib/scene/events.ts).

### Живой слой
[lib/live/](lib/live/) связывает экраны между собой: `/chat/N/` и `/victim/N/`
играют переписку вживую, а команды режиссёра долетают до соседней машины.

**Почему не WebSocket.** Серверного рантайма нет, а `ws` — лишняя зависимость,
которой на площадке может не оказаться. Задача асимметрична и раскладывается на
два встроенных примитива: приём — SSE (`EventSource` сам переподключается),
отправка — обычный `POST`. Оба на голом `node:http` внутри того же сервера,
что раздаёт страницы ([scripts/serve.mjs](scripts/serve.mjs)).

Шина ([lib/live/bus.ts](lib/live/bus.ts)) работает по двум каналам сразу и
склеивает их дедупликацией по id конверта:

| Канал | Когда | Что покрывает |
|---|---|---|
| `BroadcastChannel` | всегда, в т.ч. `npm run dev` | окна одной машины |
| SSE + POST на `/live` | когда `npm start` отвечает | разные машины локалки |

В `npm run dev` моста нет: шина обнаруживает это за пару секунд, закрывает
поток и молча остаётся на вкладках. Двух вкладок хватает, чтобы проверить всю
логику; сам транспорт проверяется на `npm run build && npm start`.

Комнаты две: `seat-N` — переписка места, `scene` — команды режиссёра (они
общие для всех экранов, `Ctrl+Alt+2` на `/chat/3` обязан вспыхнуть и на
`/wall`). Сервер держит журнал сообщений, поэтому `F5` посреди дубля доигрывает
переписку, а `Ctrl+Alt+R` журнал чистит — иначе сброшенный дубль воскреснет
на первом же обновлении экрана.

Правила при доработке:
- **Одно событие — один путь.** Тап жертвы по фишинговой ссылке шлёт обычный
  `link.opened`, тот же, что висит на `Ctrl+Alt+9`, а не собственный тип
  сообщения. Иначе у одного события появятся две реализации и они разойдутся.
- Отправитель рисует свою реплику сразу, не дожидаясь эха: в кадре сообщение
  должно появляться в момент нажатия Enter. Эхо от сервера — это подтверждение
  доставки (вторая галочка), а не сама реплика.
- Служебные строки чатера (`from: "system"`) на телефон жертвы не попадают,
  как и подсветка стоп-слов: это его детектор, а не её экран.

## Правила вёрстки под камеру

1. **Экран, а не документ.** Вёрстка под 1920×1080, `overflow: hidden` на
   `body`, скролл только внутри панелей.
2. **Нет пустоты.** Наполовину пустая таблица или панель в кадре читается как
   макет. Списки должны уходить за нижний край.
3. **Фон `zinc-950`** — светлый монитор бликует и пересвечивает лицо актёра.
4. **Высокий контраст акцентов:** прибыль `emerald-400`, отказ `rose-500`,
   давление `amber-400`, VIP `fuchsia-400`. У каждого экрана свой фирменный
   цвет: оператор `emerald`, дроповод `violet`, чатер `cyan`.
5. **Ничего лишнего в кадре:** выделение текста, фокус-кольца, контекстное
   меню и системные скроллбары отключены глобально.
6. **Табличные цифры** (`.tnum`) везде, где число меняется, иначе счётчик
   дёргается по ширине.
7. **Анимации на CSS, не на JS.** Один общий тикер вместо полусотни
   `setInterval`.
8. **Никаких чужих логотипов.** У `lightweight-charts` для этого выключен
   `attributionLogo`.
9. **Лента чата открывается снизу без JS.** В [/chat](components/chat/ChatThread.tsx)
   и на [телефоне жертвы](components/victim/PhoneThread.tsx) переписка рисуется
   `flex-col-reverse`, поэтому сообщения хранятся новыми вперёд (как история
   операций у дроповода), а панель сама упирается в нижний край. Автоскролла
   на рефах в проекте нет и быть не должно.

## Юридическая гигиена

- Все бренды вымышленные и собраны в [lib/brand.ts](lib/brand.ts).
- Телефоны — из диапазонов, зарезервированных для кино, и дополнительно
  маскируются функцией `maskPhone`.
- Ни одного реального человека, компании или домена.

При добавлении контента держитесь этих правил.
